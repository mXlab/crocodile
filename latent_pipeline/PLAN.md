# Latent Vector Pipeline — Implementation Plan

## Context

The Crocodile project needs a pipeline to invert Dauphinais' video frames into StyleGAN2 W-space and associate those W vectors with synchronized physiological biodata. This enables a future biodata→W regressor for real-time avatar generation.

This plan covers Stages 1-4: frame extraction, CNN encoder training, validation, and biodata→W dataset assembly.

## Pool Structure (descriptor-based)

Each data source is a peer-level pool described by a `pool.yaml` descriptor file. The training code discovers pools by scanning for these descriptors and applies losses based on declared properties.

| Pool | Source | biodata | emotions | temporal | feeling_it |
|------|--------|---------|----------|----------|------------|
| **session_1S** | `videos/video_1S.mov` | Yes | Yes | Yes | Yes |
| **session_2S** | `videos/video_2S.mov` | Yes | Yes | Yes | Yes |
| **session_3S** | `videos/video_3S.mov` | Yes | Yes | Yes | Yes |
| **session_4S** | `videos/video_4S.mov` | Yes | Yes | Yes | Yes |
| **session_1X** | `videos/video_1X.mov` | No | Yes | Yes | Yes |
| **gan_images** | `Diverse/` | No | No | No | No |

Loss routing by property:
- **LPIPS reconstruction**: all pools
- **Temporal smoothness**: pools with `has_temporal_continuity: true`
- **Emotion contrastive**: pools with `has_emotions: true`
- **feeling_it weighting**: pools with `has_feeling_it: true`
- **Biodata mapping (Stage 4)**: pools with `has_biodata: true`

## Step 4: StyleGAN2 Module + Encoder Model

### 4a. StyleGAN2 utilities

**File**: `latent_pipeline/models/stylegan.py`

Centralises all StyleGAN2 interactions so that training, generation, and validation scripts share the same loading and generation logic. No StyleGAN boilerplate in scripts.

```python
def load_stylegan(config, device) -> G:
    """Load G_ema from pickle; sets eval, requires_grad_(False), pure-PyTorch ops."""

def compute_w_mean(G, device, n_samples=10000) -> Tensor:
    """Average W over many Z→W samples. Used as truncation anchor."""

def sample_w(G, n, psi=1.0, seed=None, device='cpu', w_mean=None) -> Tensor:
    """Sample n W vectors: Z → G.mapping → optional truncation. Returns (n, 512)."""

def generate(G, w_batch, resolution=None) -> Tensor:
    """@torch.no_grad(). Full synthesis (resolution=None) or truncated synthesis.
    Returns (B, 3, H, W) in [-1, 1]."""

def generate_with_grad(G, w_batch, resolution=None) -> Tensor:
    """Same as generate() but without @no_grad — for training loops where gradients
    must flow back through G to the encoder."""
```

**Truncated synthesis**: StyleGAN2 generates progressively (4→8→16→…→2048). Every block has a `torgb` layer, so synthesis can stop at any resolution. At `resolution=128`, 4 expensive high-res blocks (256→2048) are skipped — roughly 5–10× faster and dramatically lower VRAM.

### 4b. Encoder model

**File**: `latent_pipeline/models/encoder.py`

#### EmotionEncoder
- Input: (B, 3, 256, 256) in [-1, 1]  *(frames on disk stay at 256 regardless of train_resolution)*
- 5-block VGG-style CNN: 32→64→128→256→512 channels, MaxPool after each block
- Spatial attention: Conv2d(512, 1, 1) → Softmax over spatial positions → weighted sum → (B, 512)
- Regressor: Linear(512, 512) → LayerNorm → ReLU → Dropout(0.3) → Linear(512, 512)
- Output: (B, 512) W vector (unbounded)
- Dynamic shapes: works at any spatial resolution (4×4 at 128, 8×8 at 256)

**Verification**: Forward pass works (random input → encoder → W → G → image).

## Step 6: Dataset + DataLoader

**File**: `latent_pipeline/data/dataset.py`

### CrocodileEncoderDataset
- Loads from `cnn_training_manifest.csv` + reads all `pool.yaml` descriptors to build a property lookup per pool_name
- Returns: image (256×256, [-1,1]), pool_name, frame_number, emotion_label (int, -1 for "none"), feeling_it (float), has_biodata (bool), has_emotions (bool), has_temporal_continuity (bool), is_consecutive (bool)
- `is_consecutive`: True if previous manifest row has same pool_name and frame_number differs by exactly 24 (1 second at 24fps). Only meaningful for pools with `has_temporal_continuity: true`.
- Loss routing uses the pool properties directly — no hardcoded pool type checks

### Custom BatchSampler
- ~50% of batches: consecutive frame pairs from temporal pools (for temporal loss signal)
- ~50% of batches: random frames from any pool
- `pair_batch_size = max(1, batch_size // 2)` to handle batch_size=1

### Train/Val split
- Train: session_1S, session_2S, session_3S + session_1X + gan_images
- Val: session_4S
- Test: ~30 held-out frames from train sessions (for Stage 7)

## Step 7: Loss Functions + Training Loop (Stage 2)

**File**: `latent_pipeline/scripts/stage2_train.py`

### Two-phase training strategy

**Phase 2A — Synthetic pre-training** (optional but recommended):
- Sample W vectors on-the-fly via `sample_w()`, generate images via `generate_with_grad()` at `train_resolution`
- Loss: MSE(encoder(image), W) — pure supervised regression, no LPIPS, no real data
- No generator in the loss computation graph except as image source
- Fast convergence: encoder learns approximate W-space geometry before seeing real faces
- Run for a few epochs until W prediction MSE is low

**Phase 2B — Real-data fine-tuning**:
- Train on `cnn_training_manifest.csv` frames (real video + diverse images)
- Losses (all below):
  1. **LPIPS (VGG)**: Primary. All pools. `generate_with_grad()` at `train_resolution`, downsample to `train_resolution` for comparison. feeling_it weighting (3×) for pools with `has_feeling_it: true`.
  2. **Pixel MSE**: Direct gradient signal, prevents collapse. Weight: 2.0.
  3. **W-diversity**: Log-std over a 256-entry FIFO queue of recent W vectors. Weight: 0.1.
  4. **Temporal smoothness**: MSE between consecutive W vectors. Weight: 0.1. Only `is_consecutive=True` frames from temporal pools.
  5. **Emotion contrastive**: Same-emotion closer, different-emotion apart (margin=2.0). Weight: 0.05.

### Critical implementation notes
- `generate_with_grad()` must be used in the training loop (not `generate()`) so that LPIPS and MSE gradients flow back through G to w to the encoder
- `G.requires_grad_(False)` prevents G's parameters from accumulating gradients, but the computation graph is tracked through G's activations
- `generate()` (with `@torch.no_grad()`) is used in `validate()` and `save_visual_grid()`

### Training config
- `train_resolution`: 128 to start (fast, low VRAM); change to 256 once confirmed working
- batch_size: 1 at `train_resolution=128/256`; increase if VRAM allows
- gradient_accumulation_steps: 16 (effective batch = 16)
- Optimizer: Adam, lr=5e-4
- Scheduler: CosineAnnealingLR, eta_min=1e-6
- Gradient clipping: max_norm=1.0
- Epochs: 5 for initial debugging, scale up once verified

### Memory management (RTX 3060, 6GB VRAM)
- FP16 autocast is **incompatible** with StyleGAN2's reference implementations (AssertionError)
- Use FP32 + `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`
- Full 2048 synthesis with gradient tracking requires ~4GB+ VRAM; truncated 128/256 synthesis uses dramatically less

### Logging (every epoch)
- train_loss_total, train_loss_lpips, train_loss_mse, train_loss_diversity, train_loss_temporal, train_loss_emotion
- val_loss_lpips (on session_4S)

### Visual checks
- `save_visual_grid()` samples evenly spaced frames across all pools (including gan_images) to show input diversity
- `quick_recon.py` for on-demand reconstruction check from any checkpoint

### Checkpointing
- Save best model (lowest val_lpips) + latest model → `latent_pipeline/outputs/`

**Verification**: Loss decreases over first 5 epochs. Visual grid shows diverse originals and input-specific reconstructions (not all faces identical).

## Configurable Training Resolution

Set `train_resolution` in `configs/default.yaml` to control generator truncation:

| Resolution | Generator blocks used | Expected batch_size | Speed vs full 2048 |
|---|---|---|---|
| 128 | 4→128 (6 blocks) | 2–4 | ~5–10× faster |
| 256 | 4→256 (7 blocks) | 1–2 | ~2–3× faster |
| 2048 | all blocks | 1 | baseline (slow) |

Start at 128 to iterate quickly and catch bugs. Once loss curves look healthy, increase to 256 for higher-quality reconstructions.
